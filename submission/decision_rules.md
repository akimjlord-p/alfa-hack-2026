# Правила и упрощения

## Анкета

`question_order` задаёт базовые вопросы отрасли и цели, затем ветку сельского хозяйства, маркетплейсов, контрактов, активов или кассового разрыва. После этого идут структура расходов, первый транш, отсрочка поставщика, бюджет, возврат выручки, возраст, форма, выручка, свободный поток, обеспечение и долги. `choices_for_question` фильтрует быстрые цели по отрасли; сервер повторно проверяет `choice_id`.

Свободный ответ проходит через Yandex AI Studio только для извлечения нормализованных фактов. Модель обязана вернуть цитату из последнего сообщения; неизвестные поля и неверные диапазоны удаляются. ИИ не формирует вопросы и не завершает анкету.

## Фильтр каталога и рейтинг

Предложение исключается, если цель не входит в `purposes`, сумма не входит в `[min_amount, max_amount]` или обеспечение отсутствует в `collateral`. Остальные предложения сортируются по убыванию суммы:

`instrument (22–35) + cashflow (0–20) + catalogue_fit (16–20) + payment_capacity (0–15) + speed (0–5) + ai_context (0–5)`.

Платёж — аннуитетный стресс-тест при условных 35% годовых. Это не ставка, ПСК и не вероятность одобрения. Ставка из каталога показывается, но сейчас не входит в балл; условия предложений `unverified`.

## Заявка и воркер

После отправки создаются `credit_applications`, `application_events` и `worker_jobs(kind=precheck_application)`. Воркер сначала обрабатывает заявки, затем медленные проверки доступности источников. Первичная проверка:

- сумма вне вилки продукта → `needs_info`;
- действующая просрочка → `needs_info`;
- неизвестная форма бизнеса → `needs_info`;
- иначе → `under_review`.

Решение эксперта — отдельный переход и отдельное событие. Это намеренно локальная симуляция; банковские скоринги и внешние проверки не вызываются.
