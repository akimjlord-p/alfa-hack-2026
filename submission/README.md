# akimai — комплект для проверки

Это комплект сдачи прототипа «кредитного кабинета предпринимателя». Основной сценарий: предприниматель отвечает на адаптивные вопросы, получает ленту конкретных банковских продуктов, подаёт синтетическую демо-заявку, видит её таймлайн, а кредитный эксперт открывает очередь и меняет статус.

## Быстрый маршрут жюри

1. Запустить проект из корня: `docker compose up --build -d`.
2. Открыть `http://localhost:8000`.
3. Выбрать «Строительство», затем «Строительство или модернизация» и пройти оставшиеся быстрые ответы. Для сценария с карточками можно использовать `1 млн ₽`, «2–3 месяца», «1–3 года», «ИП», «до 1 млн ₽», «меньше 100 тыс. ₽», «без залога», «нет кредитов и просрочек».
4. В любой карточке нажать «Подать демо-заявку». Данные формы синтетические; нажать «Отправить заявку».
5. В карточке заявки увидеть статус «Отправлена», затем «На рассмотрении» после фоновой первичной проверки. Это локальная модель, не запрос в банк.
6. Нажать «Демо-кабинет эксперта». Войти: `reviewer_demo` / `reviewer-2026`. Открыть демо-заявку, добавить комментарий и выбрать «Запросить уточнение», «Одобрить в демо» или «Отклонить в демо».
7. Для демонстрации ветки уточнения в очереди уже есть заявка «ООО «Север»» со статусом «Нужны уточнения». Предпринимательская роль: `entrepreneur_demo` / `entrepreneur-2026`; она используется как тестовая учётная запись и не даёт доступа к очереди эксперта.

Публичный стенд для просмотра командой: `https://95.216.156.245/`. На стенде нужен Basic Auth, учётные данные передаются отдельно от репозитория; сертификат по IP самоподписанный.

## Состав папки

- `openapi.json` и `openapi.yaml` — схема фактически работающего FastAPI;
- `api.md` и `postman_collection.json` — маршрут запросов и импортируемая коллекция;
- `test_scenarios.md` — повторяемые сценарии с предусловиями и ожидаемыми результатами;
- `decision_rules.md` — правила анкеты, первичной проверки, статусов и рейтинга;
- `architecture.svg`, `application_states.svg`, `data_model.svg` — схемы, соответствующие коду;
- `demodata.md` — тестовые аккаунты, синтетические заявки и границы имитаций;
- `THIRD_PARTY_NOTICES.md` — версии, лицензии и внешние сервисы;
- `requirements.lock` — фактический список Python-пакетов из собранного контейнера;
- `presentation.pptx` — краткая презентация проекта.

## Честные границы прототипа

Предложения каталога являются демоданными и помечены `unverified`; воркер проверяет доступность страниц, но не подтверждает банковские ставки и лимиты. Первичная проверка заявки — прозрачное локальное правило. Одобрение и отказ в кабинете эксперта — демонстрационные статусы. Внешняя банковская заявка, бюро кредитных историй, ЭЦП и юридически значимое решение не выполняются.

## Проверки

```powershell
python -m unittest discover -s tests -v
$env:PLAYWRIGHT_CORE_PATH = Join-Path $env:TEMP 'akimai-browser\node_modules\playwright-core'
node scripts/browser_smoke.js
```

Браузерный smoke-тест проверяет отраслевые подсказки, полный подбор, подачу заявки, фоновые статусы, мобильную ширину, пустую ленту и очередь эксперта.
