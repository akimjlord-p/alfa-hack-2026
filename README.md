# akimai

Прототип рекомендательной ленты бизнес-кредитов. Пользователь описывает задачу и профиль бизнеса, а сервис ранжирует **сценарии финансирования**, не банки: оборотный кредит, овердрафт, оборудование, бизнес-ипотека, госконтракт и другие.

## Как посмотреть дизайн

Нужен Docker Desktop. В папке проекта выполните:

```powershell
docker compose up --build
```

Откройте http://localhost:8000. PostgreSQL поднимется автоматически, сценарии и очередь воркера заполнятся при первом старте. Остановить: `docker compose down`.

Чтобы включить ИИ-опросник через Yandex AI Studio (официально рекомендуемый Python-клиент OpenAI для совместимого API), создайте файл `.env` рядом с `docker-compose.yml`:

```text
YANDEX_FOLDER_ID=идентификатор_каталога
YANDEX_API_KEY=ключ_сервисного_аккаунта
YANDEX_MODEL=aliceai-llm-flash
```

Затем перезапустите `docker compose up --build`. Без ключа или при ошибке провайдера анкета продолжает работать по правилам. Секреты остаются в `.env` и не попадают в Git или контекст сборки Docker. Ключу нужны права на вызов языковых моделей в указанном каталоге.

## Что внутри

- `credit_scenarios` — нормализованные сценарии кредитования, их вилки и ограничения;
- `sources` — реестр первичных открытых источников;
- `worker_jobs` — очередь фоновых задач;
- `match_runs` — анонимизированный журнал запусков подбора;
- `app/worker.py` — фоновая проверка доступности URL источников; она **не** подтверждает ставки и условия продуктов;
- `POST /api/match` — проверка совместимости по цели, сумме и обеспечению, затем объяснимые баллы по типу инструмента, сроку, профилю, оценке платежа и срочности. Это не вероятность одобрения.
- `GET /api/questionnaire` — версия, опорные вопросы, пояснения и варианты быстрых ответов;
- `POST /api/intake/start` и `POST /api/intake/{session_id}/message` — адаптивная анкета с сохранением сессии в PostgreSQL. В сообщении передайте `choice_id` текущего варианта или свободный `text`.
- `POST /api/applications` и `GET /api/applications/{id}` — подача демо-заявки из карточки, таймлайн статусов и результат локальной первичной проверки;
- `POST /api/demo/login`, `GET /api/reviewer/applications`, `POST /api/reviewer/applications/{id}/transition` — демо-роли предпринимателя и кредитного эксперта, запрос уточнений, одобрение и отказ;

Правила ветвления, достаточности профиля и обработки свободного ответа описаны в [документации опросника](docs/questionnaire.md). Проверка: `python -m unittest discover -s tests -v`.

Для production воркеру нужно добавить адаптеры официальных API/страниц, юридически согласованный парсинг, версионирование условий и контроль человеком перед публикацией изменений.

Комплект материалов для проверки лежит в [папке сдачи](submission/README.md): там есть маршрут демо, OpenAPI, Postman, сценарии, правила решения, схемы и презентация.

## Публикация на отдельном сервере

`docker-compose.prod.yml` запускает PostgreSQL без внешнего порта, приложение и воркер во внутренней сети и Caddy с HTTPS и паролем для демонстрации. Не совмещайте этот Compose-проект с уже работающим сервисом: разместите код отдельно, например в `/opt/akimai`. Домен для временного просмотра не нужен: в `.env.production.example` указан IP сервера. При таком варианте Caddy выпустит локальный сертификат и браузер другого участника покажет предупреждение о недоверенном сертификате. Позже можно направить домен на сервер и заменить `SITE_ADDRESS` на него для обычного HTTPS. Создайте `.env.production` по образцу `.env.production.example`. Значение `DEMO_PASSWORD_HASH` создайте командой из образца; символы `$` в файле окружения Compose нужно записать как `$$`.

Запуск из каталога проекта:

```sh
docker compose --env-file .env.production -f docker-compose.prod.yml up --build -d
docker compose --env-file .env.production -f docker-compose.prod.yml ps
```

Открывайте `https://95.216.156.245` и передайте зрителю отдельные логин и пароль. Для доступа нужны открытые порты 80 и 443. Не публикуйте `.env.production` и не открывайте порт PostgreSQL наружу.
